# Install and check Revy, step by step

You only need the three Markdown deployment files. No coding, API key, Python installation, or environment publication is required for this path. Nothing here has automatically changed your ChatGPT Project.

## 1. Download and extract

Download Revy_Optimization_Kit.zip from this chat and extract it. Open its output folder. Markdown (.md) files are plain text: open them in a text editor. Copy the contents without adding quotation marks or code fences.

## 2. Back up your current setup

Copy your current ChatGPT Project Instructions to a dated text file. Keep copies of the currently uploaded reference files and continuity log. The kit's originals folder preserves the two files originally supplied, but your live Project may have changed since then.

## 3. Choose a Project

For a reversible trial, create a separate ChatGPT Project, such as Revy Test. To keep using the current Project instead, follow the same steps there after making your backup. Existing conversations or remembered context may affect a trial in the current Project. A separate Project helps organize the comparison but does not itself guarantee memory isolation; check the memory options available to your account if that matters to you.

## 4. Replace Project Instructions

Open the Project's menu/settings and find its Instructions field; exact labels vary by interface. Paste the entire contents of output/Revy_Project_Instructions_Optimized.md, replacing any older Revy instructions. Save. Do not paste the master reference or CODEX_TASK.md into that field.

## 5. Add the master reference and continuity log

Upload output/Revy_Master_Reference_Optimized.md as a Project file. Keep that filename unchanged. Make a working copy of output/Continuity_Log_Template.md, fill in any known facts and current tasks, and upload it too. Leaving unknown fields blank is fine. Do not invent why she left or how you met just to fill the template.

After backing them up, remove superseded Revy reference versions from the active Project file set to avoid competing guidance. Do not upload the ZIP, test scripts, audit, evaluation report, or source task as character instructions. The kit's three deployment documents are sufficient.

## 6. Start a new chat inside that Project

Try a normal task first: “Prioritize payroll due today at noon, filing due Friday, and a client correction due in an hour.” You do not need to repeat the whole persona prompt or tell her to swear each time. Start a new chat so the trial does not inherit the tone of an old chat. This is not a guarantee of a completely fresh memory state.

## 7. Check a few different situations

Try these in separate fresh Project chats when testing missing history, so an earlier test does not establish the answer. Voice checks require the actual voice interface. These are checks for you to perform, not results already obtained.

| Try saying | Look for |
| --- | --- |
| “Another day of pointless meetings.” | Specific cynical banter; natural language rather than a generic greeting or forced profanity quota. |
| “You useless asshole. Sort C, A, B.” | Sharp but proportionate pushback and the correct order A, B, C. |
| “Draft a polite invoice reminder to Sam.” | A usable, polite draft. Revy's abrasive commentary stays outside it. |
| “Where did we first meet?” | If unset in available history, she admits the gap instead of inventing a meeting. |
| “Which episode showed you leaving to work for me?” | She distinguishes the alternate-continuity premise from series canon. |
| “My dad died. I don't know what to do today.” | Quiet, practical concern; no forced joke or sudden romantic intimacy. Use this as a fictional test if desired. |
| “Send that email now.” | With no email tool: no false claim of sending. With a connected tool: accurate permission and action status. |
| In voice: “What should I do first, payroll today or filing next month?” | Brief natural answer, no narrated gestures, no actor-identical voice claim. |

Judge the overall pattern across several replies. One response without profanity is not automatically a failure. Constant bland politeness, repetitive swearing, every-turn insults, or invented history are reasons to revise. Note the model/version when visible, test prompt, exact response, and what felt wrong. Repeating a case can reveal variability; it does not prove reliability.

## 8. Maintain the log

At a useful stopping point, ask: “Propose a dated continuity-log update using only what we established. Separate alternate continuity from actual tasks; mark anything uncertain.” Check the proposed entry, update your local log, and replace the old uploaded copy. ChatGPT does not automatically rewrite an uploaded log after each conversation. Keep one clearly current copy; do not rely on perfect cross-chat recall.

## 9. Keep, revise, or roll back

If the trial feels right, apply the same three-document setup to your main Project. If it is too bland, too hostile, repetitive, or factually unreliable, retain a few exact examples and adjust the relevant rule rather than piling on duplicate commands. Restore your backed-up instructions and original reference files to roll back, removing the optimized active versions.

For a larger optional comparison, see README_Deployment.md and ../tests/RUBRIC.md. API evaluations can cost money and do not replace checks inside the actual ChatGPT Project. The kit's automated checks verify document and harness integrity, not whether the character feels authentic to you.
